## Familiarity and choice

**Jakob’s Law** encourages familiar conventions. A conventional navigation label can help visitors apply existing knowledge. Novel visuals can still work around that familiar structure.

**Hick’s Law** connects decision time with the number and complexity of choices. Group related options and give users a meaningful next step; arbitrarily splitting a simple task into many screens can create new friction.

**Tesler’s Law** asks where unavoidable complexity should live. A booking form may need scheduling rules, but the application can evaluate those rules instead of making users memorize them.

Nielsen’s heuristics similarly treat consistency, visible status, and error prevention as broad evaluation tools. Use them to identify questions to test rather than as proof that a design will succeed. [Usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/).

## Movement and memory

**Fitts’s Law** relates pointing time to target size and distance. Make the visible button easy to reach and the entire label clickable. Allow enough separation to avoid accidental activation. [Fitts’s Law](https://www.nngroup.com/articles/fitts-law/).

**Miller’s Law** is often simplified into a rule to show exactly seven items. That is not a universal interface limit. Favor recognition: expose useful labels, preserve selected values, and avoid asking people to remember data from a previous screen. [Recognition and recall](https://www.nngroup.com/articles/recognition-and-recall/).

**Postel’s Law** suggests accepting reasonable input variation. For a phone field, tolerate spacing and normalize it; report genuinely ambiguous input rather than silently guessing.

## Feedback and attention

**The peak–end rule** draws attention to emotionally significant moments and the ending. A clear confirmation page can make the completion of a long process understandable.

**The aesthetic–usability effect** describes how appearance can influence perceived usability. Good styling supports confidence, but it does not repair a broken workflow.

**The von Restorff effect** suggests making an important item distinctive. If every element glows, nothing establishes a useful hierarchy.

**The Doherty threshold** emphasizes responsive interaction. Treat it as motivation to measure latency, rather than a universal 400 ms pass/fail test. Show progress for longer operations and preserve the user’s work. [Response-time guidance](https://www.nngroup.com/articles/response-times-3-important-limits/).

## A worked review

For a hiring planner, test whether a visitor can identify the next action, enter a brief, understand what the agent is doing, and recover from an incomplete response. Observe keyboard and mobile use as well as mouse interaction.

| Review question | Design experiment |
| --- | --- |
| Is the next step obvious? | One primary action with a descriptive label |
| Can input errors be fixed? | Preserve the brief and explain the field error |
| Does waiting feel uncertain? | Show status and allow a safe retry |
| Is the outcome clear? | Show the generated plan and its next action |
